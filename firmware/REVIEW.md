| 级别 | 问题与触发条件 | 修复与验证 |
|---|---|---|
| P1 | Seeed 局刷窗口调用方传入闭区间终点，但底层又减1；单行和跨256像素边界时尤其危险 | 独立的 UC8179 传输层使用一致的闭区间，测试最右下角单像素高窗口和完整800×480端点 |
| P1 | 驱动等待 BUSY 无超时；屏幕异常可使时钟主循环永久停止 | 每次等待上限20秒，返回失败，60秒后重试；实际传输代码通过模拟 BUSY 永不释放测试 |
| P1 | 原接口无返回状态，内存分配失败/显示失败仍把新图复制为“已显示” | 只有全部刷新成功才提交 `shown`；失败标记面板状态不确定，下次完整同步；不会报告显示成功 |
| P1 | 面板休眠后局刷只送新帧，未显式恢复旧帧，无法保证差分所需状态 | 每次局刷都提供对应窗口的旧、新像素；模拟总线检查0x10与0x13载荷，真实波形仍需观察 |
| P2 | 新页脚覆盖原有“部分数据离线”提示，Mac采集失败时可能看似新鲜 | PPR2协议新增受CRC保护的数据源状态，设备显示OFFLINE，长时间无新底图另显示CACHED |
| P2 | 网络包在显示刷新期间排队，消费时直接使用发送时间，造成额外走时滞后 | 队列记录接收时的单调时钟，应用时补偿排队时长 |
| P2 | 数据包允许2100年前时间，但当前Arduino时间库为32位time_t | 协议上限收紧到2038年前，避免日期转换溢出 |
| P2 | HTTP认证使用字符串constant-time比较，非ASCII输入会抛异常 | 改为字节比较，并限制连接读取等待时间；坏快照仍返回503 |
| P2 | 缺少可运行的持久数据接口，默认固件没有联网配置 | 数据接口并入现有登录服务；认证token单独本地保存；复用设备已有Wi-Fi，以mDNS发现Mac并保留当前地址后备 |
| P1 | 默认上传流程可能覆盖原厂启动配置和图片分区 | 禁用通用上传；专用工具复核32MiB备份、当前boot/分区/OTA，只写app0，写后核对应用与受保护区域；写入中失败留在下载模式等待恢复 |

## 保留边界

- PC测试不能证明墨水屏实际波形、残影或电池续航，需刷写后验证。
- 首次/六小时维护以及显示失败恢复可整屏刷新；不是绝对零闪烁。
- 没有实现深度休眠，当前重点是走时与刷新稳定性。
- 缓存每小时持久化一次，不保证重启立即恢复最后一分钟数据。
- 数据接口仅用于可信局域网，token不放入URL，未配置公网暴露。

底层参考：[Seeed_GFX固定版本](https://github.com/Seeed-Studio/Seeed_GFX/tree/24c5094cbde79933e93565ee68119e214c48fb36)。代码不再调用其无界等待的屏幕初始化/刷新函数，仍复用其字体与波形表。

## 扩展测试发现（同日后续）

本地固件模式仍显示旧的云端连接入口；在临时关闭本地接口时，仅依据接口enabled判断模式不够可靠。已增加独立的 `device.transport=local`，关闭旧setup写入入口、阻止后台及CLI云部署。生产服务GET不再提供表单、POST返回409。新增5项回归覆盖接口开启/关闭和CLI路径。

同时新增6项协议语义与数据源离线标记测试，并将像素差分检查扩展到1000个边缘/分区边界位置。当前全套47项通过；本轮没有更改已安装的固件二进制。

## 0.3手动翻页修复

- 用户确认0.2显示正常、时钟在走且无整屏闪烁，但上下翻页无效。根因是固定ACTIVE_PAGE=0且没有按键采样，误将禁止轮播实现为禁止切页。
- 增加独立按键任务、40ms去抖、8条有界事件队列。GPIO5上一页、GPIO4下一页、GPIO3回首页，长按不连跳；没有任何定时切页路径。
- 只有成功刷新才提交已显示页；切页失败保留目标并按既有60秒策略重试。其他页不响应分钟/网络/六小时定时刷新，首页缓存仍在后台更新，返回显示最新值。
- 三张固定页嵌入应用，不改写原厂图片分区或云端清单。猫咪天气加归档时间和NOT LIVE标记。
- 新增原生导航回归：首尾翻页、回首页、长按、抖动、开机按住、计时回绕、失败不提交，以及10000分钟后台事件不切页/不重刷。全套48项通过，ESP32-S3构建通过，三张800×480 PNG人工检查。
- 手动切换整页使用全刷消除跨页残影；不能把第一屏无整屏闪烁的目视结果扩展为切页也不闪烁。用户已确认0.3实机测试通过。
